# 19 — Security

Security requirements rank second in the source-of-truth hierarchy (architecture §49), directly after approved product requirements. Where a product decision collides with security, for example a Runtruck1 quirk (docs/01 D6), the conflict is raised with the product owner. It is never resolved by weakening a server-side check.

This document summarises the threat model, the controls that exist in code today (2026-09-29) and the known gaps.

## 1. Threat model summary

**Assets.** In order of sensitivity:

1. Session tokens and password hashes.
2. Tenant business data: loads, rates, invoices and payments, settlements and driver pay, employee contracts and pay, claims (claimant names are personal data), violations, driver qualification documents.
3. Load documents in object storage.
4. The audit trail.
5. Availability of dispatch operations.

**Actors.**

| Actor                                                    | Example goal                                                           |
| -------------------------------------------------------- | ---------------------------------------------------------------------- |
| Anonymous internet user                                  | Guess passwords, forge requests from another site, probe for internals |
| Member of another tenant                                 | Read or change another company's data by guessing or replaying ids     |
| Low-privilege member (Driver, Dispatcher)                | See money or HR data, approve settlements, reset the planner           |
| Malicious or compromised insider with valid Admin rights | Rewrite history                                                        |
| Compromised dependency or leaked secret                  | Code execution, credential theft                                       |

**Entry points.**

- The Next.js web origin. It serves pages and proxies `/api/v1/*`.
- The NestJS API. It must be reachable only through the web tier or load balancer (§4).
- The worker process, which has no inbound port.
- PostgreSQL, Redis and S3 object storage (SeaweedFS locally). These must be private network services. Locally, docker-compose still publishes them on every host interface with fixed credentials (G15).

## 2. Controls in place

| Area                 | Control                                                                                                                                                                                                                                                                                | Where                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **Authentication**   | Opaque 256-bit session tokens. Only SHA-256 hashes are stored. `HttpOnly` + `SameSite=Lax` cookie, `Secure` outside development. 12-hour absolute TTL. Revocation on sign-out. User and membership status re-checked on every request.                                                 | [05](05-authentication.md), `auth/session.service.ts`, `auth/auth.controller.ts` |
| Passwords            | scrypt (N = 2^15, r = 8, p = 1, 64-byte key, 16-byte salt), constant-time comparison. A dummy hash is verified for unknown emails, so timing does not reveal accounts. One generic error for every credential failure. Password input capped at 256 characters.                        | `packages/database/src/security/password.ts`, `auth/auth.service.ts`             |
| Brute force          | Redis fixed-window limits on sign-in: 10 attempts per email and 100 per IP per 15 minutes → 429.                                                                                                                                                                                       | `auth/auth.service.ts`, `common/rate-limit/rate-limiter.service.ts`              |
| **Authorization**    | Global `PermissionsGuard`, deny by default: an undecorated route is refused and logged. Permissions come from the database on every request, never from the client.                                                                                                                    | [07](07-roles-permissions.md), `auth/permissions.guard.ts`                       |
| **Tenant isolation** | The organization comes only from the session. Every query filters by `ctx.organizationId`. Foreign ids get 404. Role lookups are constrained to the session's organization.                                                                                                            | [06](06-multi-tenancy.md)                                                        |
| **CSRF**             | `SameSite=Lax`, plus an `Origin` check. Unsafe methods, including sign-in, carrying an `Origin` other than `WEB_ORIGIN` → 403 `CROSS_ORIGIN_REJECTED`. The browser talks to a single origin through the Next.js rewrite, so no CORS is enabled.                                        | `auth/session.guard.ts`, `apps/web/next.config.ts`                               |
| **Input validation** | Zod schemas from `@runtruck/validation`, applied with `ZodValidationPipe` → 400 `VALIDATION_ERROR` with field paths. List limits are capped at 500 (`pageQuerySchema`). The same schemas are reused in the web only to save round trips.                                               | `common/validation/zod-validation.pipe.ts`, `packages/validation`                |
| **Error hygiene**    | `AllExceptionsFilter`: only `AppError` messages reach users. Framework HTTP errors get fixed safe messages. Everything else is `500 INTERNAL_ERROR` with a generic message, logged server-side with the request id and stack. Unit tests assert that SQL text and secrets do not leak. | `common/errors/*`                                                                |
| Health endpoint      | Reports only up/down (`DEPENDENCY_UNAVAILABLE`), never hosts, versions or error text.                                                                                                                                                                                                  | `health/health.controller.ts`                                                    |
| **HTTP hardening**   | API: `helmet()` default headers, `x-powered-by` disabled. Web: `poweredByHeader: false`.                                                                                                                                                                                               | `app.module.ts`, `create-app.ts`, `next.config.ts`                               |
| **Secrets**          | Configuration comes only from environment variables and is validated at boot (`@runtruck/config`). Validation errors name the variable, never its value. `.env` files are git-ignored. `.env.example` holds only throwaway local values. `DEMO_TODAY` is refused in production.        | `packages/config/src/env.ts`, `.gitignore`, `.env.example`                       |
| **Audit**            | `AuditService.record(tx, ctx, …)` writes `audit_logs` in the same transaction as the change: actor, action, entity, previous/next, request id. Migration `0001_audit_append_only` adds `audit_logs_append_only_trg`, which rejects `UPDATE` and `DELETE`; `apps/api/test/auth.int.test.ts` ("writes an append-only audit trail") proves it. The table owner and superusers can still bypass it (G1). | `audit/audit.service.ts`, `packages/database/drizzle/0001_audit_append_only.sql` |
| **Object storage**   | The buckets `runtruck-documents` and `runtruck-documents-test` (SeaweedFS S3 locally) are **private**: only the configured identity can read or write, and no anonymous access is configured. Binaries never live in PostgreSQL (architecture §21).                                                                                                          | `infrastructure/docker/docker-compose.yml`                                       |
| Correlation          | `x-request-id` on every response. It is stored on audit and event rows. An incoming id is accepted only if it matches `^[A-Za-z0-9._-]{8,128}$`.                                                                                                                                       | `common/request-context/request-context.ts`                                      |
| **Dependencies**     | Architecture §40 justification for every new dependency. The lockfile is committed. pnpm runs install scripts only for the allow-listed native packages (`onlyBuiltDependencies` in `pnpm-workspace.yaml`). Password hashing uses Node's built-in crypto, so it adds no dependency.    | `pnpm-workspace.yaml`, `pnpm-lock.yaml`                                          |
| Code quality         | Strict TypeScript, `no-explicit-any`, type-aware `typescript-eslint` strict rules.                                                                                                                                                                                                     | `tsconfig.base.json`, `packages/eslint-config`                                   |

## 3. Known gaps (tracked, not done)

| #   | Gap                                                                                                                                                                                                                                                                                   | Risk                                                                     | Plan                                                                                                                                             |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| G1  | **Audit append-only holds only against a non-owner role.** The trigger of `0001_audit_append_only.sql` exists and is tested (closed: the earlier "trigger does not exist" gap). But `DATABASE_URL` connects as `runtruck`, which owns the tables and is a superuser locally and in CI; an owner or superuser can `SET session_replication_role = replica`, `DISABLE TRIGGER`, `DROP TRIGGER` or `TRUNCATE audit_logs` ([03 §9.2](03-database.md)). | An insider or a compromised process with the app's credentials can rewrite history | Staging and production: migrations run as an owner role; the API and worker connect as a separate non-owner, non-superuser role without DDL or `TRUNCATE`, with `REVOKE UPDATE, DELETE, TRUNCATE ON audit_logs` ([21 §2](21-deployment.md)). |
| G2  | No password recovery, MFA, password change or session management.                                                                                                                                                                                                                     | Account takeover recovery is manual                                      | Phase 2 follow-up (needs an email provider); MFA in Phase 16                                                                                     |
| G3  | The per-email sign-in limit locks the real user out for 15 minutes after 10 bad attempts by anyone.                                                                                                                                                                                   | Targeted denial of sign-in                                               | Add a per-(email, IP) limit or a progressive delay before production.                                                                            |
| G4  | `trust proxy` is 1 hop. If the API port is reachable directly, a client can set `X-Forwarded-For` and dodge the per-IP limit. If there are more proxy hops than one in front of the web tier, all users share one IP bucket.                                                          | Rate-limit bypass or shared lockout                                      | Deploy the API on a private network behind the web tier only, and set `trust proxy` to the real hop count ([21](21-deployment.md)).              |
| G5  | A request with **no** `Origin` header passes the CSRF check.                                                                                                                                                                                                                          | Low: browsers send `Origin` on these methods                             | Keep it. Revisit when bearer tokens (mobile) arrive.                                                                                             |
| G6  | Rate limiting covers sign-in only. There is no general per-member API limit.                                                                                                                                                                                                          | Abuse and scraping by an authenticated member                            | Phase 16                                                                                                                                         |
| G7  | The web app sends no security headers (CSP, frame-ancestors, HSTS). Helmet runs only on the API.                                                                                                                                                                                      | Clickjacking and XSS impact larger than necessary                        | Add `headers()` in `next.config.ts` and HSTS at the edge (Phase 16). The CSP must allow the Google Fonts stylesheet and the inline theme script. |
| G8  | No PostgreSQL row-level security. Tenant isolation depends on every query carrying the filter.                                                                                                                                                                                        | A missed filter leaks data                                               | Integration tests with a second organization ([20](20-testing.md)). RLS is a Phase 16 candidate.                                                 |
| G9  | **CI exists** (`.github/workflows/ci.yml`: install → lint → type check → unit tests → integration tests → build → e2e; closed: the earlier "no CI" gap). Remaining: no `pnpm audit` / dependency-vulnerability gate, and the "Unit tests" step (`pnpm test` = `turbo run test`) also runs the Playwright suite because `tests/e2e` names its script `test`, so the job fails before the real e2e step. | Vulnerable dependencies merge unnoticed; a red CI hides real regressions | Rename the e2e script to `test:e2e` (root `test:e2e` → `pnpm --filter @runtruck/e2e test:e2e`); add a `pnpm audit --prod` step. |
| G10 | Expired and revoked sessions are never purged (`purgeStale()` is not scheduled).                                                                                                                                                                                                      | Table growth. Stale rows keep IP and user-agent data longer than needed. | Repeatable job ([18](18-background-jobs.md) §6)                                                                                                  |
| G11 | Local SeaweedFS uses a single admin identity (dev only). The `S3_*` variables are validated at boot (`apiEnvSchema` in `packages/config/src/env.ts`; closed). | Over-privileged keys if copied beyond development | Use a bucket-scoped key outside development ([21 §2](21-deployment.md)). |
| G12 | Sign-in and sign-out writes are not wrapped in one transaction ([05](05-authentication.md) §10).                                                                                                                                                                                      | An audit row can be missing after a crash                                | Wrap them in `db.transaction`.                                                                                                                   |
| G13 | Upload validation (size, MIME sniffing, malware scanning) is not implemented yet. The documents module is in progress.                                                                                                                                                                | Hostile files stored and served                                          | Enforce limits in `POST /loads/:id/documents` (see `docs/api/documents.md`). Scanning is a Phase 11 follow-up.                                   |
| G15 | The docker-compose services publish on all host interfaces (`'5432:5432'`, `'6379:6379'`, `'9000:8333'`) with fixed credentials and a password-less Redis. | Anyone on the developer's network can read or change the dev and test databases, the session store and the document bucket | Bind to loopback (`'127.0.0.1:5432:5432'`, `'127.0.0.1:6379:6379'`, `'127.0.0.1:9000:8333'`) in `infrastructure/docker/docker-compose.yml`; optionally `--requirepass` for Redis with `REDIS_URL` updated in `.env.example` and CI. |
| G14 | No secrets manager. Environment files only.                                                                                                                                                                                                                                           | Secret sprawl in production                                              | Phase 16 (deployment)                                                                                                                            |

## 4. Rules for contributors

- Never disable or bypass a guard, the Origin check or a tenant filter to make a test or a quirk work (architecture §43).
- `GET` handlers must not change state (§2 CSRF).
- Every new route declares `@RequirePermissions`, `@AuthenticatedOnly` or `@Public`. Treat `@Public` as a security review item.
- Validate every body, query and params object with a Zod schema. Never trust ids, roles, permissions or organization ids sent by the client.
- Throw `AppError` with user-safe messages. Never interpolate SQL, stack traces, file paths or secrets into messages.
- Write the audit row and the outbox event in the same transaction as the change.
- New dependencies need the §40 justification in the pull request.
- Never commit `.env` or real credentials. Document new variables in `.env.example` with a safe local value, and add them to the `@runtruck/config` schema.
