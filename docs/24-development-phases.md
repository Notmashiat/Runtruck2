# 24 — Development Phases

Runtruck is built in the controlled phases of architecture §47. The current release (docs/01 D3, §5) covers **Phases 1–4 fully** and a **Runtruck1-parity slice** of Phases 5–8 and 11–13. Phases 9, 10, 14 and 15 are out of this release. Production deployment (Phase 16) is also out.

A phase or feature counts as done only when architecture §45 holds: requirements, security, tenant isolation, permissions, validation, passing tests and build, and acceptance criteria. Anything short of that is reported as partial (§43).

## 3. Definition of done for the parity slice

For each Runtruck1 screen:

1. The API endpoints in the domain's `docs/api/*.md` are implemented. Each declares its permission from [07](07-roles-permissions.md) §6 and filters by organization. Writes audit and emit their events ([17](17-event-architecture.md) §5).
2. The seed contains exactly Runtruck1's records (docs/01 §4). KPIs are computed from rows (D5).
3. The web screen matches Runtruck1: strings, classes, layout, dark mode, quirks (D6), and the D7 rendering of demo loads.
4. Unit, integration (401/403/404-cross-tenant/400/happy path) and e2e tests pass ([20](20-testing.md)).
5. Stub controls stay inert and remain listed in docs/01 §7.

## 4. Keeping this document current

Update the status column in the same change that completes or regresses a phase item. Never mark a row Done without the §45 evidence: tests run and build passed.
